# Contributing

Read `PROJECT_CHARTER.md` before proposing architectural or product changes.
Work should remain within the current milestone and preserve local-first privacy,
human review, model-license transparency, and testability.

Use synthetic examples only. Never submit real platform content, private user
text, credentials, databases, exports, machine-specific paths, or personal
identifiers.

Before submitting a change, follow the checks and privacy review in
`docs/DEVELOPMENT.md`. Use meaningful commit messages that describe one coherent
outcome.
